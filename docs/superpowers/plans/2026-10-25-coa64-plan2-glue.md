# CoA64 Plan 2 — Glue (login, realm list, character select/create) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `CoA64.exe` logs in to `logon.coa-development.org` and shows the CoA login, realm list, character
select and character create exactly as 32-bit `Ascension.exe` + `Extensions.dll` does: every one of the 167
natives the original registers on the glue Lua state exists, and every custom packet the server sends before
world entry is handled.

**Architecture:** Each reconstruction source file `src/Ascension/AscX.cpp` gets a CoA counterpart
`CoA/Source/Modules/X.cpp` (namespace `CoA::X`, module entry `CoA::X::Init`, added to `s_modules` in
`CoA/Source/CoA.cpp` in the reconstruction's `AscBindings::InitModules` order). Logic and module state that do
not touch client code live in `X.cpp` and are unit-tested; anything that calls decomp client code lives in
`XClient.cpp` (the Plan 1 `LuaReg`/`LuaRegClient` split), because `CoATests` links `CoA` without the client.
Hooks are source edits at the decomp function, marked `// CoA: <recon file:function> (orig hook 0xADDR)`.

**Tech Stack:** C++ (MSVC v143, VS 2022), CMake + Ninja, x64; the decomp's Lua 5.1, `CDataStore`, `SFile`;
Python 3 stdlib for tools.

**Spec:** `docs/superpowers/specs/2026-10-25-coa64-client-design.md` (design phase 3).

**Scope.** In: the 167 glue-state natives (`kGlueBindings` in `CoA/Source/Runtime/BindingStates.generated.inc`),
all packet handlers, hooks and events of the files they come from that feed glue screens, the in-process
replacement for MemoryBridge (the glue Vanity/Mythic natives read it), and a live side-by-side login test.
Out (Plan 3+): world-only natives of mixed files (e.g. most of `AscMisc`, `AscGlobalsB..J`, `AscCAMgr`,
`AscSpellText`), world hooks, Discord (`0x4DB9F0`), Warden, world entry. A file ported partly here keeps its
remaining world natives for Plan 3+ in the same `Modules/X.cpp`.

## Review Focus

1. **Glue → world → glue.** Logging out to character select rebuilds the glue Lua state; every glue native
   must be registered again, and module state the original keeps across logout (character list, configs,
   realm info) must still answer. Task 8 tests a second glue registration after a world one.
2. **Packets the server never sends.** A local server, or the UI asking before `SMSG_REALM_INFO` /
   `SMSG_UPDATE_CONFIGS` arrives: natives return the original's defaults, never error. Tasks 3 and 4 test
   each native against an empty store.
3. **Short or lying packets.** A count larger than the remaining bytes (`SMSG_UPDATE_CONFIGS`,
   `SMSG_CHARACTER_LIST_INFO`): reading stops the way `CDataStore` stops in the original, no crash, no read
   past the buffer. Tasks 3 and 8 feed truncated packets.
4. **Character list at its caps.** 0 characters, and the 0x80 cap on the first `SMSG_CHARACTER_LIST_INFO`
   field. Task 8 tests both.
5. **Custom WTF paths.** `ReadCustomWTF`/`WriteCustomWTF` with a missing file, an empty file and a name
   containing `..\`: the original's results (nil / empty / whatever its path handling does — reproduce, do not
   sanitize beyond it). Task 4 tests all three.
