# Quest log of 64 quests: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Quests in server slots 25–63 behave in CoA64 and in `Ascension.exe` + `Extensions.dll` exactly like
quests in slots 0–24, fed by a new server packet that only capable clients receive.

**Architecture:** The server keeps slots 0–24 in the player update fields and sends slots 25–63 (plus scaled
level and reward XP) as SMSG 0x8F7 after the client announces support with CMSG 0x8F6. Each client keeps
those 39 entries in a store owned by a new module, and every quest-log function reads slots through one
accessor. CoA64 (source) is the reference; the DLL ports the same functions as detours at the CoA64
`// OFFSET:` addresses.

**Tech Stack:** C++ (AzerothCore server, CoA64 x64 MSVC, DLL x86 MSVC), Google Test (server), CoATests (CoA64),
Python-driven host-compiled harness (DLL `tests/`), CoA gameplay scenarios (JSON), IDA (`F:\WorkDir\genuine\`).

**Spec:** `F:\WorkDir\CoA64\docs\superpowers\specs\2026-11-25-quest-log-64-design.md`

## Global Constraints

- Opcodes: CMSG `0x8F6` HELLO `{u8 version=1, u8 clientMaxSlots=64}`; SMSG `0x8F7`
  `{u8 version=1, u8 flags(bit0=full), u8 logSize, u8 count, count x {u8 slot, u32 questId, u32 state, u16 counters[4], u32 time, u32 level, u32 rewardXP}}`, entry size 29 bytes.
- Slots in 0x8F7 are 25..63 only; `questId 0` clears a slot; every occupied slot is sent even at or above `logSize`.
- A packet with an unknown version, a slot outside 25..63, or fewer bytes than `4 + count*29` is ignored whole.
- Sessions that never send a valid HELLO keep today's behaviour exactly (window, COAQLOG, 25-slot limits).
- `level` / `rewardXP` equal what `AscensionQuestLog::SendSlot` would send for the same quest.
- Client constants: `kQuestLogNativeSlots = 25`, `kQuestLogMaxSlots = 64`; display `logSize` defaults to 25 until a packet arrives.
- Branch `feat/quest-log-64` in all three repos (CoA64's exists with the spec).
- Server: verify only through `python -B tools/verify_all.py` (repo rule; no direct `ctest`/`unit_tests`).
- DLL: build into `out/` only, never `build/` (`build/Extensions.dll` is the genuine DLL).
- CoA64: inline comments 1–2 lines, enforced by `node --test "Tools/__tests__/*.test.mjs"`; decomp edits carry a `// CoA:` comment.

## Review Focus

1. **Promotion 40 → 3 in one tick**: the client must end with the quest exactly once. The server sends the 0x8F7
   clear for slot 40 in the same tick as the update-field change (Task 2 test `PromotionClearsOverflowSlotSameTick`).
2. **Updated client against a server without the feature**: no 0x8F7 ever arrives; `LogSize()` stays 25 and slots
   25–63 read empty (Task 5 test `QuestLogExtended_NoPacketMeansNative`).
3. **Hostile or truncated 0x8F7**: slot 70, count larger than the payload, version 2 → store unchanged (Task 5 test
   `QuestLogExtended_RejectsMalformed`, mirrored in Task 9).
4. **Character switch and /reload**: the store is cleared on the glue screen and kept across /reload, and
   QUEST_LOG_UPDATE fires after a snapshot (Task 5 test `QuestLogExtended_ClearedOnGlue`; in-game check in Task 8).
5. **`Quests.LogSize` lowered by a config reload** while quests sit above it: they are still sent (Task 1 test
   `SnapshotIncludesSlotsAboveLogSize`).
