# CoA64 DXVK Plan: Vulkan D3D9 renderer (default on) and the HD path

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** CoA64 renders through an x64 DXVK v2.5.3 `d3d9.dll` built from source, loaded from `<exe dir>\x64\`
(the install's own `d3d9.dll` is the 32-bit DXVK of Ascension.exe), on by default with `-nodxvk` to turn it off; when
it loads, `CoA::Hd::SetVulkanRenderer(true)` so the HD archives (patch-Q/R/V...) and HD*.dbc tables apply.

**Not in this plan:** a Vulkan backend of our own, DXVK patches, d3d10/11/dxgi, Warden (next plan).

**Architecture:** DXVK is built by meson + ninja from pinned tag `v2.5.3` (commit `c707d90`) through a CMake
`ExternalProject` (`ThirdParty/dxvk/CMakeLists.txt`), output `bin/Win/x64/d3d9.dll`. Runtime module
`CoA/Source/Runtime/Dxvk.{h,cpp}` (pure decision + `DxvkClient.cpp` Win32 half) preloads the library at startup,
before any MPQ opens, so the archive filter in RealmDataClient (which runs at archive open) already sees
`Hd::Available()`. Both `ILoadD3dLib` (CGxDeviceD3d 0x68ED80, CGxDeviceD3d9Ex 0x6A0AA0) take the preloaded handle via
`CoA::Dxvk::D3d9Library()` and fall back to `LoadLibraryA("d3d9.dll")` (marked CoA64 source edit).

**Findings for implementers:**
- The startup call site is `InitializeGlobal()` in `WoW/Source/Client.cpp` (0x4067F0): call `CoA::DxvkClient::Preload()`
  immediately before `OpenArchives();` (~line 1770); CmdLineProcess has already run there, and RealmDataClient's archive
  filter (RealmDataClient.cpp:333, `-hd 0` or `!Hd::Available()`) runs inside OpenArchives. Make sure the Extensions.log
  sink is usable at that point (check Log.h / Lifecycle.h); if not, buffer the line and log it once the log opens.
- meson.exe / ninja.exe live in `%APPDATA%\Python\Python314\Scripts` (not on PATH); `find_program` must search there
  as a HINT in addition to PATH. glslangValidator is in `%VULKAN_SDK%\Bin`.
- A ready git checkout of v2.5.3 with submodules is at `F:\WorkDir\_dxvk\dxvk-2.5.3` (scratch build output
  `build.x64/src/d3d9/d3d9.dll`); the ExternalProject must still fetch from the pinned git URL, but you may set
  `FETCHCONTENT`-style local override via a cache var `DXVK_SOURCE_DIR` (when set, use it instead of cloning) to avoid
  network in this session.
- BuildCoA64.bat checks `Wow64.exe` / `Wow64.map` but copies `CoA64.exe` / `.map`; leave that pre-existing quirk alone
  unless it blocks the zip, and only add `x64\d3d9.dll` (as `x64\d3d9.dll` inside the zip) plus the `dxvk` target.

**Tech:** meson 1.6.1, ninja 1.11.1.3 (user Python), MSVC x64 (vcvars64), Vulkan SDK `glslangValidator`
(`%VULKAN_SDK%\Bin`). Proven by a scratch build at `F:\WorkDir\_dxvk\build64.bat`.

## Global Constraints

- DXVK pinned to v2.5.3 = the version the install ships for Ascension.exe; meson options: d3d9 only
  (`-Denable_d3d8=false -Denable_d3d10=false -Denable_d3d11=false -Denable_dxgi=false`), `--buildtype=release`.
- `WOWDECOMP_BUILD_DXVK` CMake option, default ON; when meson / ninja / glslangValidator are missing, configure warns
  and skips DXVK (the client still builds and falls back to system D3D9) -- never a hard build failure.
- The install's `dxvk.conf` (working directory D:\WoW\Coa) applies unchanged; DXVK reads it from the CWD.
- HD stays off whenever the Vulkan d3d9 did not load (`-nodxvk`, file missing, load failure, wrong arch).
- No change to D3D9 device code beyond the library handle.

## Review Focus

1. Ordering: `Dxvk::Preload` runs before the first archive opens (else HD archives are filtered out even with DXVK).
2. A 32-bit or missing `x64\d3d9.dll`: error 193 / 126 logged, system d3d9 used, HD off, no crash.
3. `-nodxvk` and `-hd 0` are independent: `-hd 0` with DXVK = DXVK on, HD off.
4. The preloaded module is not freed by `IUnloadD3dLib` on a device reset path that reloads (refcount: each
   `ILoadD3dLib` takes its own `LoadLibraryW` reference to the same full path).
5. The zip from `BuildCoA64.bat` includes `x64\d3d9.dll`.

### Task 2: Dxvk runtime module and the HD switch

**Files:** Create `CoA/Source/Runtime/Dxvk.h`, `Dxvk.cpp` (pure), `DxvkClient.cpp` (Win32 Deps),
`CoA/Tests/DxvkTest.cpp`; modify both `ILoadD3dLib`, the startup call site (before the first SFile archive open --
find it in WoW/Source/Client.cpp), CoA CMake lists.

**Interfaces:**
- `struct CoA::Dxvk::Deps { bool (*hasArg)(const char*); std::wstring (*exeDir)(); void* (*load)(const std::wstring&, uint32_t& err); void (*log)(const char*); }`
- `void CoA::Dxvk::Preload(const Deps&)`: `-nodxvk` -> log "DXVK disabled (-nodxvk)", no load. Else load
  `exeDir + L"\\x64\\d3d9.dll"`; success -> keep handle, `Hd::SetVulkanRenderer(true)`, log "DXVK loaded: <path>";
  failure -> log "DXVK not loaded (error N), using system d3d9", HD stays off.
- `void* CoA::Dxvk::D3d9Library()`: a new reference to the DXVK module (`LoadLibraryW` of the same path) or nullptr.
- `bool CoA::Dxvk::Active()`.

**Tests (DxvkTest.cpp):** `-nodxvk` -> no load call, `Hd::Available()` false; load ok -> path is
`<exeDir>\x64\d3d9.dll`, `Active()` and `Hd::Available()` true; load fails with 193 -> false/false and the log line
carries 193; `D3d9Library()` null when inactive. Each RED first.

**Engine edits:** `d3dLib = static_cast<HINSTANCE>(CoA::Dxvk::D3d9Library()); if (!d3dLib) d3dLib = LoadLibraryA("d3d9.dll");`
with a `// CoA64:` comment in both files.
